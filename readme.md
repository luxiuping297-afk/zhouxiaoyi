# A股筛选雷达

真实数据采集与严格筛选版本。**仅筛选沪深主板普通A股，排除创业板（含30开头特殊代码）、科创板、北交所及ST、*ST。** 历史和盘中扫描共用采集端排除策略，指定代码也不能绕过；不能核实名称或市场身份时不参与筛选。已删除演示行情。五项条件全部通过才入选；任一必要输入缺失、过期或口径不一致，显示“无法判断”。

**当前可以扫描沪深主板非ST历史候选，尚不能确认盘中正式入选**：腾讯全A证券列表用于核验排除前后数量，先剔除范围外证券，再采集历史/盘中数据；东方财富财报与业绩预告按候选逐股核验。当前交易时段分钟累计量、主力资金和有效报价仍未完整验证，保持“无法判断”。历史候选与正式入选分别显示，不将接口失败解释为市场零只入选。详见 [历史扫描](docs/historical-market.md)。

## 运行

Python 3.10+，仅标准库，无需安装依赖。

```bash
# 实测五类接口并保存网页检测报告；不可用时退出码为2
python3 scripts/probe.py

# 接口预检通过后扫描全A股；不完整时输出诊断并退出码2
python3 scripts/scan.py --preflight

# 先扫描少量自选股验证（不是全市场）
python3 scripts/scan.py --preflight --symbols 600519,000001

# 调查个股时可不加 --preflight；仍逐项严格验证，不会绕过数据检查
python3 scripts/scan.py --symbols 600519

# 免费源沪深主板非ST历史候选；休市也可以核验已完成交易日
python3 scripts/scan_history_market.py --workers 8

# 查看网页
python3 app.py --host 0.0.0.0 --port 8000
```

本机运行时在浏览器地址栏输入 `http://127.0.0.1:8000`。也可用 `python3 -m http.server 8000 --directory static`。
网页“读取最新扫描结果”只重新读取 JSON，不会触发采集、替换数据源或刷新供应商数据。必须重新运行采集程序才能生成新结果。
全市场逐股采集可能耗时较长，先用指定股票验证。`--limit N` 可限制扫描数量，但网页会标明非全量。默认并发2，最高4。

## 规则的精确定义

1. 使用最近120个**已完成交易日**的前复权日线。前期高点为前三天上涨开始之前（截至D-3）的最高价；最低价必须出现在该高点之后且不晚于D-3。高点至低点跌幅必须严格超过20%。止跌向上暂量化为 D-3、D-2、D-1 收盘依次上升，并且 D0 当前价格高于供应商昨收。这不是对趋势未来走势的保证。
2. D-2、D-1 的正式日涨跌幅与 D0 的当前涨幅均为 `(0%, 3%]`。D0 使用供应商昨收而非简单拿未调整日线收盘计算，处理除权日基准。
3. 比较 D-2/D-3 和 D-1/D-2 的全天成交量；D0 使用已完成的一分钟数据累计至截止分钟，与 D-1 同一分钟累计量相比，三组增幅均为 `(0%, 50%]`。不会用昨日全天量、时间比例推算或当前未完成分钟代替；缺失分钟不会补零。
4. 最新正式财报归母净利润严格大于0；或最新报告期、最新公告版本的正式预告类型为“扭亏”，相关净利润预计下限>0且上年同期<0。已被正式财报覆盖的预告不再生效。财报缺失时无法确认预告是否被覆盖，保守标为无法判断。
5. D0 主力资金净流入严格大于0。统计口径为供应商的大单+超大单；缺少当天时间戳不能认定为当前数据。

报价、分钟数据和资金时间最多延迟180秒；只支持北京时间连续竞价扫描时段。开盘集合竞价、收盘集合竞价、休市及无法对齐分钟数据时显示无法判断。新股不足120个交易日、历史停牌缺量、重复记录、零分母、非数值也无法判断。
这些规则按证券市场的北京时间判断，网页逐股显示行情时间、判断时间、条件证据、数据来源及采集时间。
结果过期自动转为无法判断，不再显示为当前入选；任一条件不满足且其他必要数据完整时显示“不满足”。

## GitHub Pages 部署

1. 提交并推送所有项目文件到 `main`。
2. 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。
3. **Actions → Deploy stock radar to GitHub Pages → Run workflow** 可部署网页；勾选 `refresh_history` 扫描沪深主板非ST历史候选；勾选 `refresh_data` 会探测、采集盘中数据。可在 `symbols` 填入逗号分隔的代码（只影响盘中扫描），留空扫描完整的沪深主板非ST池；指定代码仍执行相同排除。
4. 接口不完整时工作流会发布诊断页面，**不会声称采集成功**；代码错误或测试失败会阻止部署。部署地址以工作流 `github-pages` 输出为准。

网站源文件位于 `static/`，发布前由 `scripts/build_site.py` 验证并生成发布目录，同时提供站点根路径及旧 `/static/` 兼容入口；`build.json` 记录发布提交，网页页脚显示版本。不需要后台或构建依赖。
GitHub Pages 是静态展示；GitHub Actions 手动采集不是实时行情服务。工作流有排队和部署延迟，超过180秒的结果不会当作当前入选；没有设置自动定时采集，也没有宣称覆盖当前整个市场。
若要稳定盘中全市场扫描，需要可用的批量数据接口与常驻采集服务；应在验证所需数据和接口权限后再采购或部署。

```bash
python3 -m unittest discover -s tests -v
node tests/test_frontend.cjs
```

测试中的人工输入仅用于边界测试，绝不发布为真实市场结果。退出码0为测试通过；采集退出码2表示接口不可用、必要数据缺失或扫描未完成，不能当作成功。

## 主要文件

- `radar/engine.py`：严格规则、时间与完整性检查。
- `radar/provider.py`：候选真实接口适配与明确错误状态。
- `scripts/probe.py`：逐类接口探测。
- `scripts/scan.py`：采集、评估、原子保存结果。
- `static/results.json`：真实扫描结果或失败诊断；没有演示股票。
- `static/capabilities.json`：真实接口检测报告。
- `static/index.html`、`app.js`、`style.css`：网页与明细展示。
- `.github/workflows/pages.yml`：验证、可选采集及网页部署。
- `docs/data-sources.md`：接口证据、网络需求和付费数据要求。

本次未接入收费API，没有密钥写入仓库。密钥只允许放在采集端环境变量或 Actions Secrets，不能放在公开静态资源中。
